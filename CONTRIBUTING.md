# Contributing to ResearchMind

Thank you for your interest in contributing to **ResearchMind** — the evidence-grounded autonomous AI research platform for NLP.

ResearchMind is designed to uphold rigorous scientific integrity, reproducible evaluations, and production-quality software architecture.

---

## Code of Conduct

All contributors must adhere to our [Code of Conduct](CODE_OF_CONDUCT.md). Please be respectful and constructive in all interactions.

---

## Core Engineering Principles

1. **Evidence Grounding**: No feature should fabricate scientific claims, benchmark scores, or citations. Every claim generated by the system must trace back to a verified document chunk or explicit experimental run.
2. **Modularity**: Adhere to clean architecture (`app/api`, `app/core`, `app/models`, `app/nlp`, `app/retrieval`, `app/services`, `app/agents`). Avoid monolithic files.
3. **Reproducibility**: Experiments must capture exact seeds, hyperparameters, model versions, and git commit hashes.
4. **Offline Capability & Mock Mode**: The system must remain fully functional in `LLM_PROVIDER=demo` mode without requiring external paid API keys.

## Development Setup

### 1. Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate  # On Windows: .venv\Scripts\activate
pip install -r requirements.txt -r requirements-dev.txt

# Run migrations / initialize SQLite local DB
python local_main.py

# Run tests
pytest
```

### 2. Frontend

```bash
cd frontend
npm install
npm run dev      # Launches Vite dev server at http://localhost:5173
npm run build    # Type-check and compile bundle
```

---

## Pull Request Checklist

Before submitting a Pull Request, please ensure:

- [ ] All backend unit and integration tests pass (`pytest backend/tests`).
- [ ] Frontend builds with zero TypeScript errors (`npm run build` in `frontend/`).
- [ ] Code follows PEP 8 for Python and ESLint/Prettier standards for TypeScript.
- [ ] New features include corresponding automated tests and documentation updates.
- [ ] No API keys, credentials, or private data are committed to git.

---

## Reporting Issues

If you find a bug or have a feature request:
1. Check existing GitHub Issues to see if it has already been reported.
2. File a new issue with a clear description, reproduction steps, expected behavior, and environment details.
